يحتاج كود المنصات إلى مشروع React مع Tailwind CSS v4. تستخدم هذه الخطوات Next.js، وتُذكر الأطر الأخرى في الختام.

## مشروع جديد [#new-project]

<Steps>
<Step>

### أنشئ تطبيق Next.js

```bash title="الطرفية"
npx create-next-app@latest my-app --ts --tailwind --app
```

</Step>
<Step>

### هيّئ كود المنصات

```bash title="الطرفية"
npx shadcn@latest init https://dga.omqkhafi.dev/r/dga.json
```

العنصر `dga` من النوع `registry:base`. يكتب الملف `components.json` بالإعدادات `iconLibrary: "hugeicons"` و`rtl: true` ونمط Base UI والسجل `@dga`، فيعمل الأمر `npx shadcn@latest add @dga/button` مباشرة. ويثبّت `@base-ui/react` و`cn` و`class-variance-authority` وHugeicons. كما يضيف كل رموز DGA والسمة الداكنة والأنماط المتجاوبة إلى `globals.css`، ويهيّئ خط IBM Plex Sans Arabic عبر `next/font`.

</Step>
<Step>

### حدّد اللغة والاتجاه

```tsx title="app/layout.tsx"
<html lang="ar" dir="rtl">
```

استخدم `lang="en" dir="ltr"` للصفحات الإنجليزية. لا تحتاج المكوّنات إلى أي تغيير آخر.

</Step>
</Steps>

## مشروع shadcn قائم [#existing-shadcn-project]

إن كان في المشروع ملف `components.json`، فأضف النمط مباشرة:

```bash title="الطرفية"
npx shadcn@latest add https://dga.omqkhafi.dev/r/dga-style.json
```

يدمج سطر الأوامر قيم DGA في ملف `globals.css` الخاص بك. وتصبح متغيرات shadcn الموجودة لديك (`--background` و`--primary` …) مرتبطة برموز DGA، فتأخذ مكوّنات shadcn الأصلية في `components/ui` ألوان DGA أيضًا. وهذا هو التغيير الوحيد في سمتك؛ أما رموز DGA فمتغيرات جديدة لا وجود لها في مشروع shadcn الأصلي. أما المكوّنات فخطوة منفصلة ولا تمسّ `components/ui` أبدًا: انظر [أين تُثبَّت المكوّنات](#install-location).

## الرموز فقط [#tokens-only]

لاستخدام رموز DGA دون أي مكوّن (مثلًا في نظام تصميم قائم)، أضف الرموز وحدها:

```bash title="الطرفية"
npx shadcn@latest add https://dga.omqkhafi.dev/r/dga-tokens.json
```

## استخدام المساحة `@dga` [#use-the-dga-namespace]

يسجّلها `init …/dga.json` لك. وفي المشاريع الأخرى سجّلها مرة واحدة في `components.json`:

```json title="components.json"
{
  "registries": {
    "@dga": "https://dga.omqkhafi.dev/r/{name}.json"
  }
}
```

ثم ثبّت العناصر بأسمائها:

```bash title="الطرفية"
npx shadcn@latest add @dga/button @dga/badge
```

## أين تُثبَّت المكوّنات [#install-location]

يُكتب كل مكوّن من `@dga` في `components/dga/<name>.tsx`، ويُستورد من هناك:

```tsx title="page.tsx"
import { Button } from "@/components/dga/button";
```

قد يحتوي المشروع أصلًا على shadcn الأصلي، أو على مكتبة مشتقة منه، في `components/ui`. الزر `@dga/button` و`ui/button` ملفان مختلفان بواجهتين مختلفتين، فلا يشتركان في مسار واحد: تثبيت عناصر `@dga` لا يستبدل ولا يعيد تسمية ولا يستورد أي شيء من `components/ui`، ويمكن استخدام الاثنين معًا. والاستيراد بين عناصر `@dga` (يستخدم Field المكوّن Input، ويستخدم Search Box المكوّن Input) يشير إلى `@/components/dga/*` وليس إلى `components/ui`.

يُشترك في أمرين عن قصد:

- الملف `lib/utils.ts` يصدّر `cn`، وهو موجود أصلًا في كل مشروع shadcn. وتستورد نسخة `@dga` الدالة `cn` من الحزمة `cn`. يسأل سطر الأوامر قبل استبدال `lib/utils.ts` الموجود، وتصلح أي إجابة لأن التوقيع واحد.
- الملف `lib/dga/direction.tsx` (العنصر `direction` الذي تستخدمه Tabs وMenu وTooltip وغيرها) داخل مجلد `dga` حتى لا يتعارض مع مساعد بالاسم نفسه.

### لماذا `target` وليس اسمًا بديلًا [#install-target]

يكتب سطر أوامر shadcn ملف `registry:ui` في الاسم البديل `ui` من `components.json` (`@/components/ui` افتراضيًا). ووضع `@dga` هناك يتعارض مع shadcn الأصلي، وحلّ ذلك بالأسماء البديلة يلزم كل مستخدم بتعديل `components.json`. لذلك يعلن كل ملف في `@dga` الحقل `files[].target` (`components/dga/button.tsx`)، ويحترمه سطر الأوامر لكل أنواع العناصر، نسبةً إلى المشروع (وإلى `src/` إن وُجد)، دون أي تغيير في `components.json`. ويعيد سطر الأوامر كتابة الاستيراد بين العناصر إلى الأسماء البديلة (`@/components/ui/input`) ويُبقي الاستيراد الذي يشير إلى ملف موجود، فكان `components/ui/input.tsx` الأصلي سيُلتقط بصمت. لذلك تستورد مصادر السجل `@/components/dga/*` مباشرة، ويثبّت الأمر `bun run test:install` عناصر `@dga` في مشروع فيه `button` و`input` و`dialog` الأصلية، ويتحقق أن تلك الملفات لم يتغير منها بايت واحد وأن المشروع يُبنى.

## الوضع الداكن [#dark-mode]

تُطبَّق الرموز الداكنة تحت `.dark` (next-themes وshadcn) أو `[data-theme="dark"]` (عُرف موقع DGA). يعمل الاثنان على `<html>` أو على أي عنصر، فيمكن أن يكون قسم واحد داكنًا.

```tsx title="page.tsx"
<section data-theme="dark">…</section>
```

## أطر أخرى [#other-frameworks]

مع Vite أو React Router أو TanStack Start، شغّل أمر `init` نفسه. وخارج Next.js يثبّت سطر الأوامر الخط من `@fontsource/ibm-plex-sans-arabic` بدل `next/font`.

## جهّز وكيل الذكاء الاصطناعي [#set-up-your-ai-agent]

يبني وكيل البرمجة أفضل حين تكون قواعد المشروع أمامه. تثبّت صفحة [إعداد الوكيل](/docs/ai/skills) المهارة وملفي `AGENTS.md` و`CLAUDE.md`، وتسرد [التوثيق للوكلاء](/docs/ai/llm) كل صفحة بصيغة Markdown، ويتيح [خادم MCP](/docs/ai/mcp) لمساعد أن يتصفح مكوّنات `@dga` ويضيفها.

## ما يُثبَّت [#what-gets-installed]

| العنصر | النوع | المحتوى |
| --- | --- | --- |
| [`dga`](/r/dga.json) | `registry:base` | إعدادات `components.json` (Hugeicons، واتجاه RTL، ونمط Base UI، والسجل `@dga`)، ويسحب `dga-style` |
| [`dga-style`](/r/dga-style.json) | `registry:style` | الاعتماديات واستيرادات CSS وخريطة الأنماط `cn-*` للمكوّنات، ويسحب `dga-tokens` و`utils` والخط |
| [`dga-tokens`](/r/dga-tokens.json) | `registry:theme` | كل الرموز، والسمتان الفاتحة والداكنة، والأنماط المتجاوبة، وسمة Tailwind، وربط shadcn، وطبقة الأساس |
| [`utils`](/r/utils.json) | `registry:lib` | الملف `lib/utils.ts` الذي يعيد تصدير `cn` من الحزمة `cn` (دون clsx أو tailwind-merge) |
| المكوّنات (`@dga/button` …) | `registry:ui` | `components/dga/<name>.tsx`، وليس `components/ui` أبدًا |
| [`font-ibm-plex-sans-arabic`](/r/font-ibm-plex-sans-arabic.json) | `registry:font` | خط IBM Plex Sans Arabic بالأوزان 400 إلى 700، مجموعتا الحروف العربية واللاتينية |
