## Usage

```tsx title="page.tsx"
import { Tabs, TabsContent, TabsList, TabsTrigger } from "@/components/dga/tabs";

export function RequestTabs() {
  return (
    <Tabs defaultValue="details">
      <TabsList aria-label="Request sections">
        <TabsTrigger value="details">Details</TabsTrigger>
        <TabsTrigger value="documents">Documents</TabsTrigger>
        <TabsTrigger value="history">History</TabsTrigger>
      </TabsList>
      <TabsContent value="details">Applicant name, service and submission date.</TabsContent>
      <TabsContent value="documents">Two files attached.</TabsContent>
      <TabsContent value="history">Submitted on 4 November 2026.</TabsContent>
    </Tabs>
  );
}
```

Use Tabs to split one page into parts that belong together and are read one at a time: the details, documents and history of a request. Tabs do not change the page: for moving between pages use links or a navigation menu. Tabs are not steps; use a stepper for a sequence. Every TabsTrigger needs a `value`, and the TabsContent with the same `value` is its panel. Give the list an `aria-label` if the page has more than one.

The list starts on the right, and the Left and Right arrows swap: in Arabic, Left moves to the next tab. The components read the direction from `<html dir>` themselves, so you do not wrap them in a provider.

## Anatomy

- **List** (`role="tablist"`): the row of tabs, with a 3px divider under it (`divider`). It scrolls sideways when the tabs do not fit, or with `overflow="menu"` the tabs that do not fit collapse into a More tab.
- **Tab** (`role="tab"`): an optional icon and a label. The selected tab is bold with a 3px bar in `border-primary`.
- **More tab** (`overflow="menu"`): a tab with a chevron at the end of the list that opens a menu of the tabs that do not fit. It is shown as selected while one of them is.
- **Panel** (`role="tabpanel"`): the content of the selected tab.

## Examples

### Sizes and icons

`size` is `sm`, `md` (default) or `lg`. Put an icon before the label. A disabled tab can be reached with the arrow keys but not selected.

### Vertical

`orientation="vertical"` puts the list beside the panel, with the bar on the end side. Up and Down move between tabs.

<Preview compact name="tabs-vertical" title="Vertical" />

### More menu

With `overflow="menu"` on TabsList, the tabs that do not fit the width collapse into a More tab (Base UI Menu), re-measured when the width changes. Give Tabs a `defaultValue` or `value`, and translate the label with `moreLabel`. The menu items are the hidden tabs, with the chosen one checked; <kbd>Tab</kbd> moves from the visible tabs to the More tab and <kbd>Enter</kbd>, <kbd>Space</kbd> or <kbd>ArrowDown</kbd> opens it.

<Preview compact name="tabs-more" title="More menu" />

### Behaviour

By default an arrow key moves focus and selects the tab. Set `activateOnFocus={false}` on TabsList for manual activation: arrows only move focus, and <kbd>Enter</kbd> or <kbd>Space</kbd> selects. `divider={false}` removes the line under the list, `flush` removes its side padding, and `value` with `onValueChange` makes the selection yours to control.

## Accessibility

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> | Moves focus into the list (to the selected tab), then into the panel. |
| <kbd>ArrowRight</kbd> | Moves to the next tab and opens its panel (the previous tab in Arabic). |
| <kbd>ArrowLeft</kbd> | Moves to the previous tab (the next tab in Arabic). |
| <kbd>ArrowDown</kbd> | In a vertical list, moves to the next tab (ArrowUp to the previous). |
| <kbd>Home</kbd> | Moves to the first tab (and End to the last). |

- Built on Base UI Tabs: `role="tablist"`, `tab` and `tabpanel`, with `aria-selected`, `aria-controls` and `aria-orientation`. Only the selected tab is in the tab order (roving focus).
- A tab opens its panel as soon as it gets focus. The panel itself is focusable, so keyboard users can reach content that has no focusable control.
- The selected tab is shown by bold text and a bar, not colour alone. Text is 4.5:1, icons and the bar 3:1 or better, on every surface, in light and dark. Focus is a 2px outline inside the tab.

## Deviations from DGA

- The More tab (DGA's overflow menu on horizontal tabs) is `overflow="menu"`. Scrolling sideways stays the default for lists that do not fit. Figma gives the Closed and Open More tab no sizes beyond a normal tab, so it uses the tab padding, a 16px chevron and the Menu component for the list.
- Vertical tabs also show a neutral bar on hover and press (as in the DGA CSS); every tab shows the primary bar when selected.
