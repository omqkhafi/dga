## Usage

```tsx title="page.tsx"
import {
  AlertDialog,
  AlertDialogAction,
  AlertDialogCancel,
  AlertDialogContent,
  AlertDialogDescription,
  AlertDialogFooter,
  AlertDialogHeader,
  AlertDialogTitle,
  AlertDialogTrigger,
} from "@/components/dga/alert-dialog";
import { Button } from "@/components/dga/button";

export function WithdrawRequest() {
  return (
    <AlertDialog>
      <AlertDialogTrigger render={<Button destructive variant="outline" />}>
        Withdraw request
      </AlertDialogTrigger>
      <AlertDialogContent>
        <AlertDialogHeader>
          <AlertDialogTitle>Withdraw this request?</AlertDialogTitle>
          <AlertDialogDescription>
            Request 24810 will be withdrawn. This cannot be undone.
          </AlertDialogDescription>
        </AlertDialogHeader>
        <AlertDialogFooter>
          <AlertDialogCancel>Keep request</AlertDialogCancel>
          <AlertDialogAction destructive onClick={withdraw}>
            Withdraw
          </AlertDialogAction>
        </AlertDialogFooter>
      </AlertDialogContent>
    </AlertDialog>
  );
}
```

Use an Alert Dialog when the next step is hard or impossible to undo and the person must choose before going on: withdrawing a request, deleting a file, signing out everywhere. It asks one question with two answers. For a form, a longer explanation or anything that is not a confirmation, use a [Dialog](/docs/components/dialog).

### Why a separate component, not a Dialog variant

It looks exactly like the Dialog (it uses the same classes), but it behaves differently in ways that matter for accessibility and cannot be a style: it has `role="alertdialog"`, so assistive technology announces it as an urgent question and reads its description straight away; focus starts on Cancel, the safe answer, not on the first control; and clicking the backdrop does not dismiss it, so people cannot lose the choice by accident. Keeping these in one small item means a Dialog never needs to guess which behaviour you want.

## Anatomy

- **Window**: the Dialog card: `background-white`, radius-md, `shadow-3xl`, 400px wide (`size="md"` is 600px), on an `alpha-black-50` backdrop.
- **Title and description**: the question, and what will happen. Both are linked to the window for screen readers.
- **Cancel**: the outline Button. Focus starts here.
- **Action**: the primary Button, or the destructive one with `destructive`. Put it last.
- There is no close button in the corner: the person answers with one of the two actions or presses Escape.

## Accessibility

| Key | Action |
| --- | --- |
| <kbd>Enter</kbd> or <kbd>Space</kbd> | On the trigger, opens the dialog. On a button, chooses it. |
| <kbd>Tab</kbd> | Moves between the two actions. Focus stays inside the dialog. |
| <kbd>Escape</kbd> | Cancels: closes the dialog and returns focus to the trigger. |

- `role="alertdialog"` with the title as its name and the description as its description. Focus starts on Cancel and returns to the trigger when the dialog closes. The page behind is inert.
- Clicking the backdrop does nothing. Escape is the keyboard way out, as in the WAI-ARIA pattern.
- Text is 4.5:1 and focus rings 3:1 or better on the window, in light and dark. The destructive action is also labelled in words, so colour is not the only cue.
- It fades and scales in; with reduced motion it appears without animation.

## Derivation from DGA
